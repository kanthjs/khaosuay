# khaosuay <img src="man/figures/khaosuay-hexlogo-nobg.png" align="right" height="139" alt="khaosuay hex logo"/>

> **ข้าวสวย** — R Package สำหรับวิเคราะห์ข้อมูลการทดลองทางเกษตรกรรมในบริบทของไทย
> เปลี่ยนข้อมูลดิบให้กลายเป็นรายงานสถิติที่พร้อมใช้งาน เหมือนข้าวสวยหุงสุกใหม่ที่พร้อมเสิร์ฟ

---

## ทำไมต้อง khaosuay ข้าวสวย?

การวิเคราะห์สถิติทางการเกษตร (เช่น RCBD, Split-plot) มักมีความยุ่งยากในการเตรียมข้อมูลและการสร้างกราฟเพื่อเขียนรายงาน `khaosuay` จึงเกิดขึ้นมาเพื่อ:

- **ลดขั้นตอนที่ซับซ้อน** — เปลี่ยน syntax ยาก ๆ ให้เป็นฟังก์ชันที่เข้าใจง่ายในคอนเซปต์การ "หุงข้าว"
- **รองรับภาษาไทย** — แก้ไขปัญหา font ภาษาไทยในกราฟที่นักวิจัยไทยมักเจอ
- **พร้อมทำรายงาน** — สร้างตาราง ANOVA และกราฟเปรียบเทียบค่าเฉลี่ยที่ใส่ตัวอักษร (a, b, c) โดยอัตโนมัติ

## ขั้นตอนการใช้งาน (The Cooking Workflow)

การใช้ `khaosuay` ง่ายเหมือนการหุงข้าวหนึ่งหม้อ แบ่งเป็น 4 ขั้นตอน:

### 1. wash_rice — เตรียมข้อมูล

```r
library(khaosuay)

clean_data <- wash_rice(my_agri_data)
```

### `wash_rice()` ทำหน้าที่
1. จัดการชื่อคอลัมน์: ปรับตัวพิมพ์เล็ก-ใหญ่ ลบช่องว่าง และเปลี่ยนชื่อคอลัมน์สำคัญให้เป็นมาตรฐาน (เช่น แปลงคำว่า "สายพันธุ์", "กรรมวิธี", "var" ให้กลายเป็น treatment อัตโนมัติ)
2. จัดการค่าว่างและเว้นวรรค: ลบช่องว่างหน้า-หลังข้อความ (Trim whitespace) และแปลงช่องว่างเปล่าๆ ให้เป็น NA
3. แปลงชนิดข้อมูล (Coercion):
- เดาและแปลงคอลัมน์ที่ควรจะเป็นตัวเลข (Numeric) อัตโนมัติ
- แปลงคอลัมน์จัดกลุ่มพื้นฐาน (เช่น treatment, rep, location, province) ให้เป็น Factor อัตโนมัติ
4. ตรวจสอบความผิดปกติของข้อมูล:
- หาแถวซ้ำ (Duplicates)
- ตรวจสอบค่าติดลบในคอลัมน์ตัวเลข
- ตรวจสอบค่าที่อยู่นอกช่วงที่กำหนด (Range Validation)
- หาค่าผิดปกติ (Outliers) ด้วยวิธี IQR หรือ Z-score
5. ตรวจสอบทางสถิติและภูมิศาสตร์:
- เช็คว่าแผนการทดลองมีความสมดุลหรือไม่ (Balanced Design Check)
- ตรวจสอบพิกัด GPS ว่าถูกต้องและอยู่ในขอบเขตประเทศไทยหรือไม่

### Arguments
- data: ข้อมูล Raw Data ของคุณ (data.frame หรือ tibble)
- treatment_col / rep_col: เอาไว้ระบุชื่อคอลัมน์ Treatment หรือ ซ้ำ แบบชี้เป้า (ถ้าไม่ระบุ ฟังก์ชันจะพยายามเดาจากชื่อคอลัมน์เอง)
- factor_cols / numeric_cols: ระบุชื่อคอลัมน์ที่ต้องการบังคับให้เป็น Factor หรือ ตัวเลข (ถ้าฟังก์ชันเดาให้ไม่ครบ)
- valid_ranges: กำหนดขอบเขตข้อมูลที่รับได้แบบเป็น List เช่น list(yield = c(0, 1500), severity = c(0, 100)) ถ้ามีค่าหลุดจากนี้จะถูกแจ้งเตือน
- design_check: TRUE/FALSE สั่งให้เช็คว่าจำนวนซ้ำ (Rep) ในแต่ละ Treatment เท่ากันหรือไม่ (เหมาะกับงานทดลองแบบมีแผน)
- outlier_method: เลือกวิธีหา Outlier ได้แก่ "iqr" (ค่าเริ่มต้น), "zscore", หรือ "none" (ไม่หา)
- remove_duplicates: ถ้าตั้งเป็น TRUE จะลบข้อมูลแถวที่ซ้ำกันทิ้งอัตโนมัติ (ค่าเริ่มต้นคือ FALSE แค่เตือนเฉยๆ)
- check_gps / thailand_only: สำหรับงานที่มีละติจูด/ลองจิจูด สั่งให้เช็คพิกัดว่าถูกต้องและอยู่ในประเทศไทยหรือไม่

### Output
Object ที่เป็น List (class "washed_rice") ซึ่งประกอบด้วย 4 ส่วน:
1. $data: Dataframe ที่ทำความสะอาดเรียบร้อยแล้ว (นำไปวิเคราะห์ต่อได้เลย)
2. $report: List สรุปรายงานอย่างละเอียดว่าฟังก์ชันแก้ไขหรือพบความผิดปกติอะไรบ้าง
3. $flagged: Dataframe ที่ดึงเฉพาะ "แถวที่มีปัญหา" (เช่น Outlier, ค่านอกช่วง, ค่าติดลบ, GPS ผิด) มาให้คุณตรวจสอบง่ายๆ
4. $column_map: ตารางเปรียบเทียบชื่อคอลัมน์เดิม กับชื่อคอลัมน์ใหม่หลังแปลงแล้ว

รูปแบบการใช้งาน
1. ใช้งานแบบด่วนที่สุด (ให้ฟังก์ชันจัดการเองทั้งหมด)

```
# ล้างข้อมูลและดึงเฉพาะ data ที่สะอาดแล้วออกมาใช้เลย
clean_data <- wash_rice(raw_data)$data
```

2. สำหรับงานแปลงทดลอง (Experimental Design)
สมมติคุณมีข้อมูลทดลอง RCBD อยากเช็คว่าจดข้อมูลมาครบไหม และผลผลิตอยู่ในช่วง 0-2000 กก. หรือไม่

```r
result <- wash_rice(my_data,
  treatment_col = "สายพันธุ์ข้าว", 
  rep_col       = "ซ้ำ",
  valid_ranges  = list(yield = c(0, 2000)),
  design_check  = TRUE # ให้เช็คว่าทุกสายพันธุ์มีจำนวนซ้ำเท่ากัน
)

clean_data <- result$data
bad_rows   <- result$flagged # ดูว่ามีแถวไหน yield เกินหรือติดลบไหม
```

3. สำหรับงานสำรวจลงพื้นที่ (Survey / Epidemiology)
สมมติเป็นการลงพื้นที่สำรวจโรคพืช มีเก็บพิกัด GPS มาด้วย

```r
result <- wash_rice(survey_data,
  valid_ranges   = list(severity = c(0, 100)), # โรคพืชต้องอยู่ระหว่าง 0-100%
  outlier_method = "zscore",                   # หาค่าโดดด้วย Z-score
  remove_duplicates = TRUE,                    # ถ้ากรอกข้อมูลซ้ำให้ลบทิ้งเลย
  check_gps      = TRUE,                       # ตรวจสอบว่าพิกัดไม่เพี้ยน
  thailand_only  = TRUE                        # เช็คว่าพิกัดอยู่ในไทย
)
```

## คำแนะนำ

`wash_rice` ถูกออกแบบมาให้ "ทำความสะอาดสิ่งที่ทำได้อัตโนมัติ" (เช่น ปรับชื่อคอลัมน์ ลบช่องว่าง) แต่จะ ไม่ลบข้อมูลที่มีแนวโน้มเป็นความผิดพลาดทางสถิติหรือการเก็บข้อมูลทิ้งโดยพลการ เพราะในงานวิจัยทางการเกษตร ค่าที่ดูแปลกๆ อาจจะเป็นการค้นพบใหม่ หรือเป็นแค่คนพิมพ์ผิดก็ได้

ข้อมูลที่จะถูกเด้งไปอยู่ในตาราง $flagged เพื่อรอให้คุณตัดสินใจต่อ มีอยู่ **4 กรณีหลัก** ดังนี้:

1. เจอค่าติดลบในคอลัมน์ตัวเลข (Negative Values)
สิ่งที่ฟังก์ชันทำ: สแกนหาค่า < 0 ในทุกคอลัมน์ที่เป็นตัวเลข แล้ว Flag แถวนั้นไว้

- สิ่งที่คุณต้องตัดสินใจ: คุณต้องดูว่าค่านั้นติดลบได้จริงไหม (เช่น อุณหภูมิ) หรือเป็นไปไม่ได้เลย (เช่น ผลผลิตข้าว, ความสูงต้น, เปอร์เซ็นต์การเกิดโรค)

- ทางแก้: หากพิมพ์ผิด (เช่น พิมพ์ -15 แทนที่จะเป็น 15) คุณต้องแก้เลขให้ถูก หรือถ้าเป็น error จากเครื่องมือ อาจจะต้องเปลี่ยนค่านั้นให้เป็น NA

2. ข้อมูลหลุดขอบเขตที่ตั้งไว้ (Domain-Specific Range)
สิ่งที่ฟังก์ชันทำ: ถ้าคุณกำหนดพารามิเตอร์ valid_ranges (เช่น ให้คะแนนโรคอยู่แค่ 0-100) ฟังก์ชันจะ Flag แถวที่มีค่าเกินหรือต่ำกว่าช่วงนี้

- สิ่งที่คุณต้องตัดสินใจ: ทำไมค่าถึงเกิน?

- ทางแก้: บ่อยครั้งเกิดจากการตกหล่นของจุดทศนิยม (พิมพ์ 1005 แทน 100.5) คุณต้องกลับไปดูสมุดจดข้อมูลดิบ (Raw data) เพื่อแก้ไขให้ถูกต้อง

3. เป็นค่าผิดปกติทางสถิติ (Outliers)
- สิ่งที่ฟังก์ชันทำ: ถ้าคุณเปิดโหมดหา Outlier (ใช้ IQR หรือ Z-score) ฟังก์ชันจะจับค่าที่ "โดด" ออกจากกลุ่มเพื่อนๆ ในคอลัมน์เดียวกันมา Flag ไว้

- สิ่งที่คุณต้องตัดสินใจ: นี่คือเรื่องที่ยากที่สุดในงานวิจัยครับ คุณต้องเลือกว่า "นี่คือของดี หรือ ขยะ?"

- ถ้าเป็นขยะ: เช่น เครื่องชั่งรวน หรือจดเลขผิด -> เปลี่ยนเป็น NA หรือตัดทิ้ง

- ถ้าเป็นของดี: เช่น ข้าวสายพันธุ์นี้ให้ผลผลิตทะลุหลอดจริงๆ (Super Yield) -> คุณต้อง เก็บค่านี้ไว้ (ปล่อยผ่าน ไม่ต้องทำอะไร)

4. พิกัด GPS ผิดเพี้ยนแบบเป็นไปไม่ได้ (Invalid GPS)
- สิ่งที่ฟังก์ชันทำ: เช็คว่า Latitude อยู่นอกช่วง [-90, 90] หรือ Longitude อยู่นอกช่วง [-180, 180] หรือไม่

- สิ่งที่คุณต้องตัดสินใจ: พิกัดนี้จดมาผิดฟอร์แมตหรือไม่?

- ทางแก้: บางคนอาจจะกรอกพิกัดสลับช่องกัน (เอา Lat ไปใส่ Lon) หรือพิมพ์เครื่องหมายผิด คุณอาจจะต้องแก้สลับคอลัมน์กัน หรือใช้โปรแกรมแผนที่เพื่อหาพิกัดที่ถูกต้องมาแทนที่

#### หมายเหตุ 

```
result <- wash_rice(raw_data, ...)
write.csv(result$flagged, "review_these.csv")
```

เมื่อพบ `$flagged` ว่ามีปัญหา ควรพิจารณาแก้ไข กกับข้อมูลที่พบว่ามีความผิดปกติ หลังจากนั้นแก้ไข ให้ถูกต้อง

## `taste_rice()` ชิมก่อนว่าควรจะปรุงอย่างไร
ครื่องมือสำหรับ "ตรวจสอบข้อตกลงเบื้องต้น" (Assumptions Check) ของข้อมูลทางสถิติก่อนที่จะเลือกใช้สถิติวิเคราะห์ที่เหมาะสม โดยเปรียบเสมือนการ "ชิมข้าว" ก่อนนำไปปรุงอาหารจริง เพื่อให้มั่นใจว่าข้อมูลของเราเหมาะกับสูตรการวิเคราะห์แบบไหน

## working 
ฟังก์ชันนี้ทำงานตามลำดับความสำคัญของสถิติ (Hierarchical Testing):

Step 1: Normality (การกระจายตัวแบบปกติ)

- ใช้ Shapiro-Wilk Test ตรวจสอบ

- กฎเหล็ก: ถ้าข้อมูล "ไม่ปกติ" (Non-normal) ฟังก์ชันจะหยุดเช็คตัวอื่น และสรุปให้ใช้ Non-parametric ทันที เพราะถือว่าผิดเงื่อนไขร้ายแรงที่สุด

Step 2: Homogeneity of Variance (ความแปรปรวนเท่ากัน)

- ใช้ Levene's Test (คำนวณจาก Median/Brown-Forsythe) ซึ่งมีความทนทาน (Robust) สูง

- จะทำขั้นตอนนี้ต่อเมื่อข้อมูลผ่าน Step 1 (Normal) มาแล้วเท่านั้น

### mode
คุณสามารถเลือกได้ 3 แบบตามความลึกที่ต้องการ:

Quick: เช็คจาก "Raw Data" แยกรายกลุ่ม เหมาะสำหรับดูภาพรวมเบื้องต้น

Model: เช็คจาก "Residuals" (ค่าส่วนเหลือ) ของโมเดล ANOVA/Linear Model ซึ่ง เป็นวิธีที่ถูกต้องตามหลักสถิติมากกว่า เมื่อใช้กับงานวิจัยแผน RCBD (มี Block)

Both: ทำทั้งสองแบบเพื่อเปรียบเทียบกัน (เป็นค่า Default)

### การจำแนกผลและการแนะนำ (Classification & Recommendation)
ฟังก์ชันจะสรุปผลออกมาเป็น 3 สถานะหลัก เพื่อบอกว่าคุณควรทำอะไรต่อ
|สถานะ (Classification) | สถิติที่แนะนำ (2 กลุ่ม) | สถิติที่แนะนำ (>= 3 กลุ่ม)|
|Normal + Equal Var| Student's t-test| Fisher's ANOVA + Tukey|
|Normal + Unequal Var| Welch's t-test| Welch's ANOVA + Games-Howell|
|Non-normal|Mann-Whitney U|Kruskal-Wallis + Dunn's|

### จุดเด่นของเวอร์ชันนี้
- ความปลอดภัย (Robustness): มีฟังก์ชัน safe_shapiro ป้องกัน Error กรณีกลุ่มตัวอย่างน้อยเกินไป ($n < 3$) หรือข้อมูลทุกตัวเท่ากันหมด ($sd = 0$)
- รองรับ RCBD: สามารถระบุคอลัมน์ block ได้ ซึ่งฟังก์ชันจะนำไปสร้างโมเดล aov(response ~ treatment + block) ให้โดยอัตโนมัติ
- Visual Diagnostic: ถ้าสั่ง plot = TRUE จะสร้างกราฟ QQ Plot (ดูความปกติ) และ Residuals vs Fitted / Boxplot (ดูความแปรปรวน) ให้เห็นด้วยตาเปล่า
- รายงานที่อ่านง่าย: verbose = TRUE จะพิมพ์สรุปเป็นขั้นตอนด้วย Emoji และสัญลักษณ์ที่เข้าใจง่าย (Decision Flow)


### วิธีการอ่านผล (Example Output)

Object ที่มี 3 ส่วนหลัก:
`$results`: ตารางสรุปสั้นๆ ว่าตัวแปรไหนผ่าน/ไม่ผ่าน
`$details`: ผลสถิติละเอียด (ค่า $W$, $F$, $p$-value)
`$verdict`: คำแนะนำเป็นประโยคภาษาไทยที่นำไปเขียนในเล่มวิจัยได้เลย

```r
# ชิมข้าวดูว่า Yield กระจายตัวดีไหม โดยมีการคุมความแปรปรวนด้วย Block (rep)
result <- taste_rice(my_data, response = "yield", block = "rep")

# ดูคำแนะนำ
result$verdict
```
